# 차기 목표 — 구도 = AI 세션 정리함 (2026-11-18 초안)

> 상태: **방향 결정 · 설계 초안.** 사용자 결정(2026-11-18)을 정리한 문서. 구현 전 남은 질문은 맨 아래.

## 1. 왜

- 지금 구도는 사람이 81칸을 직접 채우는 **나침반 · 길라잡이**다.
- 앞으로 일은 AI 세션(Claude · ChatGPT · Gemini …)으로 많이 한다. 구조 없이 세션을 열면 PC 의 정리 안 된 작업 파일처럼 쌓인다. 그러면 일이 비효율적이 되고, 인수인계받는 사람이 알 수 없다.
- 사람은 구조를 좋아하지만 업무는 다양하고 변수가 많다. 그래서 **핵심 목표 하나를 정하면 그 구조 그대로 AI 세션을 열고, 진행 현황이 다시 구도로 돌아오는** 원버튼 출발점을 만든다.
- 대상: AI 를 쓰는 일반 직장인. 출시: App Store · Microsoft Store · 웹. 서버 없이 각자 기기에서 쓰는 로컬 앱으로.

## 2. 사용자 결정 (2026-11-18)

| 질문 | 결정 |
|---|---|
| AI 와 잇는 방식 | **(가) 프롬프트 내보내기부터.** 앱이 AI 를 직접 부르지 않는다. 다음 단계(API 직접 호출 · 에이전트 연결)는 나중에 정한다 |
| 진행 관리 장소 | 내보낼 때 **사용자가 폴더를 고른다.** 앱이 그 폴더에 시작 파일들을 만들고, 사용자는 그 폴더에서 AI 세션을 시작한다 |
| 진행 현황 | AI 가 그 폴더 안에서 **구도 형식(JSON)** 으로 진행률을 관리한다. 구도 앱은 그 파일을 주기적으로 읽어 현황을 최신으로 맞춘다 |
| 동기화 백업 | Windows 앱: 구도에 저장된 목표 ↔ 내보낸 폴더의 JSON 을 동기화하고, **동기화할 때마다 날짜별 백업** |
| 세션 구조 | **핵심 목표 = 본부 세션**(항상). **세부 목표마다 세션**(항상). 그 아래 실행 과제 세션은 **작업이 필요할 때만** AI 가 만든다 |
| 팀 목표 | 팀 목표도 내보낼 수 있다. 맥락을 위해 **목표 전체를 내보내되**, 프롬프트에 **내가 맡은 블록**을 분명히 적고, AI 는 **그 블록 세션만** 만든다 |

## 3. 흐름 (초안)

```
구도 앱  ─ 목표 화면 「AI 로 내보내기」
   ├ ① 폴더 고르기 (Windows: 폴더 선택 / 웹 · 휴대폰: 파일 묶음 내려받기)
   ├ ② 시작 파일 만들기 (아래 4절)
   └ ③ 안내: "이 폴더에서 AI 를 열고 GUDO.md 를 읽게 하세요" + 프롬프트 복사 버튼
AI 세션 (사용자의 Claude · ChatGPT · Gemini …)
   ├ 본부(핵심 목표) → 세부 목표 세션들 → (필요하면) 실행 과제 세션
   └ 일할 때마다 gudo.json 의 칸 상태 · 메모를 고친다
구도 앱  ─ 「현황 가져오기」(Windows 는 주기적으로 자동)
   └ 날짜별 백업 → gudo.json 읽기 → 칸 완료 · 진행률 · 메모 반영
```

## 4. 내보낸 폴더 모양 (초안)

```
<사용자가 고른 폴더>/
  GUDO.md                       본부 지시서 — AI 가 가장 먼저 읽는다 (목표 구조 · 세션 규칙 · 파일 규칙 · 팀이면 내 블록)
  gudo.json                     진행 현황 — 구도 형식 (목표 1개 + 칸마다 상태 · 메모 · 갱신 시각)
  01-<세부 목표 이름>/README.md  세부 목표 세션의 작업 공간 · 인수인계 메모
  …
  .gudo/backups/2026-11-18.json  동기화할 때마다 날짜별 백업 (같은 날은 시각을 붙임)
```

- `gudo.json` 은 앱의 Plan 형식을 그대로 쓰고, 칸마다 `updatedAt` 을 둔다. 앱과 AI 가 같은 칸을 고쳤으면 **더 최근 것**으로 맞춘다 (팀 갱신 코드 `stamps` 와 같은 생각).
- AI 가 고쳐도 되는 것: 칸 완료 · 메모 · 하위 할 일 · 진행 메모. 목표 문장 · 구조(크기 · 블록)는 앱에서만 고친다 (규칙은 `GUDO.md` 에 적는다).
- 프롬프트는 특정 AI 에 묶이지 않는 보통 글로 쓴다.

## 5. 플랫폼별

| | 폴더 고르기 | 현황 가져오기 |
|---|---|---|
| **Windows 앱** | 폴더 선택 창 | 주기적으로 자동 + 날짜별 백업 (Electron 이 파일을 읽고 씀) |
| 웹 (PC Chrome · Edge) | 폴더 접근 API 로 가능 | 열려 있을 때 「현황 가져오기」 |
| 웹 · 휴대폰 (iPhone Safari 등) | 폴더 접근 불가 → 파일 묶음(zip) 내려받기 | `gudo.json` 을 직접 골라 가져오기 |

- 앱 **설치 경로**(Program Files 등)는 업데이트 때 덮어써지고 쓰기가 막혀 있다. 그래서 진행 파일은 사용자가 고른 폴더에, 구도 자체 데이터는 지금처럼 앱 저장소에 둔다.

## 6. 세션 규칙 (GUDO.md 에 들어갈 것)

1. 본부 세션 = 핵심 목표. 전체 그림을 들고, 세부 목표 세션을 연다.
2. 세부 목표마다 세션 하나 — 항상 연다. 이름은 「<번호>-<세부 목표>」.
3. 실행 과제 세션은 그 과제에 실제 작업이 있을 때만 연다.
4. 모든 세션은 끝날 때 `gudo.json` 의 자기 칸을 고치고, 자기 폴더 README 에 인수인계 메모를 남긴다.
5. **팀 목표:** 「당신은 <n>번 블록 <세부 목표> 담당」. 다른 블록은 읽기 전용 맥락이다. 본부 · 다른 블록 세션은 만들지 않는다.

## 7. 출시 · 정책 확인 (구현 전에)

- 앱이 AI 에 아무것도 보내지 않는다(사용자가 직접 붙여넣음). 그래서 「수집하는 데이터 없음」으로 신고할 수 있다.
- **Microsoft Store:** 스토어 앱은 스토어가 업데이트한다. 스토어용 빌드에서는 지금의 GitHub 자동 업데이트를 끈다.
- **App Store:** 웹을 감싸기만 한 앱은 거절될 수 있다(최소 기능 기준) → 네이티브 빌드(EAS) · 개발자 계정 필요. iPhone 은 폴더 동기화가 어려워 파일로 주고받는다.
