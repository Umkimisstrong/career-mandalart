# 구도 팀 — 조직 · 부서 목표로 확장하는 컨셉 (2026-11-09 초안)

개인용 구도는 **매슬로우 욕구 단계**를 바탕으로 삶의 목표를 81칸에 구조화했다. 팀용 구도는 같은 81칸 틀에 **조직의 목표 · 성과 · 과제**를 담고, **초대장**으로 블록마다 담당자를 정해 함께 점검한다.

> 상태: 컨셉 · 결정 대기. 아래 「정해야 할 것」이 정해지면 구현한다.

---

## 1. 조직 목표는 무엇을 바탕으로 구조화하나 — 자료조사

| 틀 | 무엇을 나누나 | 구도에 맞는 점 | 한계 |
|---|---|---|---|
| **균형성과표 BSC** (Kaplan · Norton, HBR 1992) | 재무 · 고객 · 내부 프로세스 · 학습과 성장 4관점 | 4관점이 **아래(학습 · 성장) → 위(재무)로 원인 → 결과 사슬**을 이룬다(전략 맵, 2004). 매슬로우처럼 「바탕부터 쌓는」 구조라 개인용과 같은 사고방식. 4 × 2 = 세부 목표 8칸에 딱 맞는다 | 비영리 · 공공기관에는 재무 관점이 잘 안 맞는다는 비판 → 「재무」를 「재원 · 효율」로 바꿔 쓰면 된다 |
| **OKR** (Andy Grove · Intel → John Doerr, 『Measure What Matters』) | 목표(Objective) 3~5개 + 숫자로 재는 핵심 결과(Key Result) | 실행 과제 칸을 **숫자 있는 핵심 결과**로 쓰게 하는 규칙. 구도의 「수량 · 기한」 단위가 이미 있다 | 「무엇을 나눌지」(분류)는 알려 주지 않는다 → BSC 와 함께 쓴다 |
| **호신 칸리 Hoshin Kanri** (일본 품질경영, X-매트릭스 · 캐치볼) | 경영 방침을 아래 층으로 펼치고(전개), 위 · 아래가 목표와 수단을 **주고받으며 협의**(캐치볼), PDCA 로 매월 · 분기 점검 | 「핵심 목표 → 8개 블록 → 담당자」가 곧 방침 전개. **초대장 = 캐치볼의 공**: 관리자가 블록을 넘기고, 담당자가 실행 과제를 채워 돌려준다 | 처음부터 「돌파 목표 8개」를 다 잡지 말라는 경고 — 8칸을 다 채우기보다 핵심 2~3개에 집중 |
| 말콤 볼드리지 (NIST) | 리더십 · 전략 · 고객 · 측정/지식 · 인력 · 운영 · 결과 7범주 | 조직 진단 점검표로 쓸 만하다 | 범주가 7개라 8칸과 어긋나고, 목표 설정보다 평가용 |
| 맥킨지 7S | 전략 · 구조 · 시스템 · 공유 가치 · 스타일 · 인력 · 역량 | 조직 변화 · 정렬 진단 | 성과 목표보다 조직 설계용 |
| 렌시오니 팀의 5가지 기능장애 | 신뢰 → 갈등 → 헌신 → 책임 → 결과 피라미드 | 팀의 「바탕」(신뢰 · 협업)을 목표로 삼는 근거 → 학습과 성장 관점의 「조직 문화」 블록에 쓴다 | 팀 건강 진단용, 성과 분류는 아님 |

**참고:** 만다라트의 원형인 **만다라 차트**는 1979년 경영 컨설턴트 마쓰무라 야스오(松村寧雄, 클로버 경영연구소)가 만들었고, 처음부터 「개인 인생 설계부터 **기업 경영 계획까지**」 쓰는 도구로 소개됐다. 81칸을 조직에 쓰는 것은 원래 쓰임새로 돌아가는 것이다. (1987년 이마이즈미 히로아키의 「만다라트」는 별개의 아이디어 발상법)

### 결론 (추천)

**바탕 = 균형성과표(BSC) 4관점 × 2 = 세부 목표 8칸**, 실행 과제 칸은 **OKR 식 숫자 핵심 결과**, 운영 방식은 **호신 칸리 식 전개 + 캐치볼(초대장) + 월 · 분기 점검**.

개인용과 짝을 맞추면:

| | 개인 구도 | 팀 구도 |
|---|---|---|
| 바탕 이론 | 매슬로우 욕구 단계 (생리 → 자기초월) | 균형성과표 4관점 (학습 · 성장 → 재무) |
| 세부 목표 8칸 | 11개 삶의 카테고리 중 고르기 | 아래 8개 조직 카테고리 중 고르기 (바꿔 쓰기 가능) |
| 실행 과제 | 행동 + 언제 · 얼마나 · 수량 | 핵심 결과(숫자 · 기한) + 담당자 |
| 점검 | 반복 점검 · 오늘의 점검 | 같은 반복 점검 + 블록 담당자별 진행률 · 주간 · 월간 점검 |

## 2. 팀 81칸 배치 — BSC 를 8칸에

3×3 에서 **아래 줄 = 바탕(학습과 성장), 가운데 줄 = 과정, 위 줄 = 결과**. 매슬로우를 아래부터 쌓은 개인용과 같은 읽는 방향.

| | | |
|---|---|---|
| 💰 **재무 · 성장** — 매출 · 시장 확대 | 🤝 **고객 가치** — 만족 · 유지 · 추천 | 📈 **재무 · 생산성** — 비용 · 수익성 |
| ⚙️ **운영 프로세스** — 품질 · 속도 · 비용 | ⭐ **핵심 목표** (팀의 올해 방침) | 💡 **혁신 프로세스** — 개선 · 신제품 · 신규 사업 |
| 🧑‍🎓 **사람 · 역량** (인적 자본) | 🫶 **조직 문화 · 팀워크** (조직 자본 · 렌시오니) | 🛠️ **정보 · 도구** (정보 자본 · 시스템) |

- 바꿔 쓸 수 있는 카테고리: **고객 관리 프로세스**(발굴 · 유지) · **규제 · 사회**(안전 · 환경 · 지역사회 · ESG) · 공공 · 비영리용 **재원 · 효율**
- 작은 크기(1 · 3 · 5 · 7칸)도 그대로: 5칸이면 4관점 하나씩, 3칸이면 「과정 · 결과」 둘
- 부서 템플릿 예: 영업팀 · 개발팀 · 마케팅팀 · 인사팀 · 고객지원팀 · 스타트업 전사 (연령대 템플릿 9종처럼)

## 3. 초대장과 권한

### 역할

| 역할 | 누가 | 할 수 있는 것 |
|---|---|---|
| **관리자** (팀 목표를 만든 사람) | 1명 (추후 공동 관리자) | 핵심 목표 · 세부 목표 8칸 쓰기, 모든 블록 보기 · 쓰기, **초대장 만들기 · 회수**, 담당자 바꾸기, **팀 목표 삭제 · 복제** (관리자만) |
| **블록 담당자** (초대받은 팀원) | 블록마다 1명 → 81칸이면 **초대장 8장** | **초대받은 블록만** 접근. 초대장마다 권한을 따로: **읽기 / 수정 / 삭제(칸 비우기)**. 핵심 목표 · 자기 세부 목표는 읽기만 |
| (선택) 열람자 | 임원 · 다른 팀 | 전체 읽기만 · 진행률 모니터링 |

- 초대장 수 = 그 크기의 세부 목표 수 (9 → 8장, 7 → 6장, 5 → 4장, 3 → 2장)
- 담당자 화면: 핵심 목표(★) + 자기 블록 3×3 만. 다른 블록은 **숨김** 또는 **진행률 숫자만** (정해야 할 것 ②)
- 팀 목표의 삭제 · 복제 · 크기 변경 · 핵심 목표 변경은 관리자만
- 담당자는 자기 블록을 **개인 구도로 가져가** 그 블록의 세부 목표를 자기 핵심 목표로 다시 81칸을 짤 수 있다 (호신 칸리의 아래 층 전개)

### 모니터링 (관리자 화면)

- 블록별 담당자 · 진행률 · 오늘/이번 주 남은 점검 · 마지막 갱신 시각
- 바탕화면 작은 창(데스크톱)에 팀 목표를 띄우면 **블록 = 담당자**, 늦은 블록이 깜빡

## 4. 기술 — 여러 사람이 같은 목표를 보려면

지금 구도는 **DB 없이** 기기마다 따로 저장한다 (결정 사항). 팀 기능은 **사람 사이에 데이터가 오가야** 해서 두 가지 길이 있다.

| | A. 서버 없이 — 「초대장 코드 · 보고 코드」 | B. 무료 클라우드 DB — Supabase |
|---|---|---|
| 방식 | 관리자가 블록마다 **초대장 코드(QR · 링크)** 를 만든다. 코드 안에 그 블록 내용과 권한, 관리자 서명이 들어간다. 담당자는 받은 블록만 갖고 일하다가 **보고 코드**를 메신저로 보낸다. 관리자 앱은 서명 · 범위를 확인하고 **그 블록만** 합친다 | 초대 링크 → 담당자 로그인(이메일) → 같은 팀 목표를 실시간으로 함께 본다. 블록별 권한은 DB 의 행 단위 보안(RLS)이 강제 |
| 실시간 | ✕ 보고 코드를 보낼 때만 갱신 (주간 보고 리듬과는 맞음) | ○ 바로 반영 |
| 권한 강제 | 읽기: 받은 블록만 갖고 있으니 자연히 제한. 수정 · 삭제: **관리자 앱이 그 블록 밖 변경을 무시**하는 방식 | 서버가 강제 (가장 확실) |
| 지금 결정과 | ✓ DB 없음 · 무료 · 개인 정보 서버에 안 남김 그대로 | ✗ 「DB 없이」 결정을 바꿔야 함. 로그인 · 개인정보 처리방침 필요 |
| 비용 · 제약 | 0원 | 무료: DB 500MB · 월 활성 사용자 5만 · 프로젝트 2개, **1주일 안 쓰면 일시정지**(수동 재개). 유료 Pro 월 $25 |
| 만드는 데 | 작다 (지금 QR 코덱 · 백업 코드 위에) | 크다 (로그인 · 동기화 · 충돌 처리 · 권한 정책) |

**호스팅 주의:** 회사 · 팀이 업무에 쓰면 **상업적 이용**이 될 수 있다. 지금 Vercel Hobby 는 비상업 전용 → 팀 기능을 남에게 열 때는 보류 중인 호스팅 결정(Cloudflare Pages 무료 이전 추천)이 먼저다.

### 추천 순서

1. **1단계 — 팀 목표 구조 (서버 불필요, 바로 가능):** `Plan.kind = 'team'`, BSC 8 카테고리 · 부서 템플릿, 블록 담당자 이름 칸, 관리자 모니터링 화면
2. **2단계 — 초대장 A (서버 없이):** 초대장 코드 · 보고 코드, 블록 범위 · 권한 확인, 관리자만 삭제 · 복제. 실제 팀 1곳에서 시험
3. **3단계 — 실시간 B:** 시험한 팀이 「실시간이 꼭 필요하다」고 하면 Supabase 로. 1 · 2단계 데이터 형식을 그대로 옮긴다

## 5. 정해야 할 것

1. **동기화 방식** — A(서버 없이, 보고 코드) 로 먼저 / 처음부터 B(Supabase, 로그인 · 실시간)
2. **담당자에게 다른 블록을** — 완전히 숨김 / 진행률 숫자만 보임 / 읽기는 다 열기
3. **권한 단위** — 초대장마다 읽기 · 수정 · 삭제를 따로 고르기(요청대로) / 「보기 전용 · 담당」 두 가지로 단순화
4. **바탕 이론** — BSC 4관점 × 2 (추천) / 다른 틀
5. **호스팅** — 팀 기능 공개 전에 Cloudflare Pages 이전 여부
